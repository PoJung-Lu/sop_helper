# SOP_Helper 專案進度與後續計畫

- 目前版本：v0.9.1
- 最後更新：2026-09-18
- 用途：讓新的對話 session 匯入本檔案後，可以直接接續開發，不需要重新解釋背景。
- 使用者環境：Windows 11、Microsoft 365 桌面版 PowerPoint、VS Code（本機模式，不使用 WSL/Docker 執行本專案）、Python 3.13.15、專案路徑範例 `C:\Users\paes2\OneDrive\桌面\Python\Work\SOP_helper`。

---

## 0. 專案目標（不要偏離的核心）

製程工程師手動用 PowerPoint 畫圓圈、箭頭來標示部件照片上的螺絲位置、扭力值與相關資訊，屬於重複且容易出錯的工作。SOP_Helper 是一個 Windows 本機桌面工具，目標：

1. 從 Excel/YAML 規格表自動帶入螺絲/元件的扭力、O-ring、塗矽油等資訊。
2. 讓使用者直接在部件照片上點擊建立標記（螺絲位置），減少手動畫圖。
3. 產生的結果可以直接複製成 **PowerPoint 原生可編輯圖形物件**（不是死圖），貼上後圓圈、箭頭、文字都可以個別修改。
4. 不需要額外伺服器、公司權限開通、雲端上傳；完全本機執行。
5. 第一版只支援「鎖螺絲」這一種步驟類型。

## 1. 目前已完成（v0.1 → v0.9.1 累積成果）

### 1.1 開發環境（已完成，不需重做）

- Windows 11 + Python 3.13.15（Windows 官方版，非 WSL 版）。
- 專案獨立虛擬環境 `.venv`（用 `python -m venv .venv` 建立）。
- PowerShell 執行原則已設定為 `RemoteSigned`（`Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`），可執行 `Activate.ps1`。
- 已安裝套件：`PySide6`、`Pillow`、`openpyxl`、`PyYAML`、`python-pptx`、`pywin32`。
- VS Code 使用本機模式（非 Remote-WSL、非 Dev Container），終端機使用 PowerShell，不影響背景執行的 WSL2 與 Docker Desktop。

### 1.2 料件規格載入（Excel / YAML）

- 支援 `.xlsx`（工作表名固定找 `components`，找不到則用第一張工作表）與 `.yaml`/`.yml`。
- 欄位（英文欄名，內容可中文）：
  ```text
  part_name, part_number, size, required_torque, torque_unit,
  applicable_model, reference_image, requires_oring, oring_spec,
  requires_silicone_grease, silicone_grease_note, torque_min, torque_max, notes
  ```
- 預設值：`applicable_model=Universal`、`requires_oring=false`、`requires_silicone_grease=false`。
- 驗證規則：
  - `part_name`、`part_number`、`size` 必填。
  - `part_number` 不可重複。
  - `required_torque` 與 `torque_unit` 必須「同時填寫」或「同時留空」，否則視為錯誤格式，擋下整份載入。
  - 兩者都留空 → 視為「無需扭力元件」（例如 O-ring），允許載入，只跳提示訊息，不算錯誤。
  - 若有 `torque_min`/`torque_max`，會檢查 `torque_min <= required_torque <= torque_max`。
- 已提供測試用範例檔 `components_sample.xlsx`（含 PT100、壓力計_JPR2、水冷板固定螺絲、三通接頭O-ring 四筆資料）。

### 1.3 扭力規則

- 單位選單固定四個選項：`kgf-cm`、`N-M`、`無需扭力`、`鎖緊就好`。
- 選料件後自動帶入規格值，使用者可以直接修改（沒有額外的「使用自訂值」按鈕，直接改）。
- 扭力數值輸入 `0` 時自動切換單位為「無需扭力」。
- 「無需扭力」：輸出時完全不顯示扭力文字/方框。
- 「鎖緊就好」：輸出時顯示文字「鎖緊就好」（一樣有方框）。

### 1.4 標記（Annotation）

- 資料結構 `Annotation`：`annotation_id`、`component_index`、`x`/`y`（0~1 相對座標）、`sequence`、`torque`、`torque_unit`、`marker_only`、`label_x`/`label_y`（目前尚未真正使用 label 位置，是保留欄位）。
- 標記順序 (`sequence`) 預設值 = 目前所有標記中最大值 + 1；可以跳號，但不可重複（重複會被對話框擋下並提示）。
- 圓圈中心的數字已改為真正置中（依文字實際寬高計算位置，1、10、100 都置中）。
- 「僅新增標記」勾選框：勾選後這個標記輸出時只顯示圓圈與順序數字，不顯示料件名稱、扭力、方框、箭頭。

### 1.5 操作模式（畫布互動，這是花最多輪迭代才穩定的部分）

- **核心規則**：左側料件清單「有沒有選取料件」決定畫布左鍵點擊的行為。
  - 沒選料件 → 點圖片＝嘗試選取附近既有標記（容許誤差半徑 22px），選中會變成藍色高亮，同步反白右側標記清單對應項目。
  - 選了料件 → 點圖片＝新增標記（跳出設定對話框）。
- 再點一次已選取的同一個料件 → 取消選取，回到「瀏覽/選取」模式。這個行為**不依賴 Qt 內建的 `isSelected()`**，改用自行維護的布林變數 `self._component_selected`，因為 Qt 內部選取狀態更新時序不穩定，之前造成「提示文字說已取消，但點圖片仍在新增標記」的 bug，v0.9.1 已修正。
- 縮放：`Ctrl + 滑鼠滾輪`，以**滑鼠游標位置為錨點**縮放（不是畫布中心），範圍 25%~400%。
- 平移：**滑鼠中鍵拖曳**（拿掉了之前設計的 `Space+左鍵`，避免跟左鍵選取/新增邏輯衝突）。
- 中央畫布工具列：`適合視窗`、`－`、`100%`、`＋`、縮放百分比顯示。
- 拖曳圖片檔案（`.png`/`.jpg`/`.jpeg`/`.bmp`）直接放到中央畫布可以載入為主圖片；若目前已有標記，會先跳出確認視窗「載入新圖片會清除目前所有標記，是否繼續？」，確認才清空重來，取消則不動作。同一邏輯也套用在按鈕「載入主圖片」。

### 1.6 右側面板

- 目前是「標記清單」與「輸出預覽」用 `QStackedWidget` 做**切換顯示**（不是同時顯示），按鈕文字會在「顯示輸出預覽」與「顯示標記清單」之間切換。
- 標記清單目前是**平面清單**（尚未分層/分群組），每行格式：`序號. 料件名稱  扭力或無需扭力  [僅標記]`（如果有勾選僅標記才顯示 `[僅標記]`）。
- 點擊清單項目會同步在畫布上高亮對應圓圈；反之點畫布圓圈也會同步反白清單項目。

### 1.7 輸出功能

- **PNG**：`render_composite()` 產生合成圖，使用微軟正黑體（`C:\Windows\Fonts\msjh.ttc`），黑色文字、紅色細圓圈與紅色細扭力方框（PNG 版 `width=1`）。找不到字型檔會直接丟錯誤，不會默默輸出亂碼。
- **PPTX（另存）**：`export_pptx()` 產生獨立可編輯物件：
  - 原始主圖：`Picture`，獨立、不群組。
  - 圓圈＋順序數字：合併寫在同一個 `Oval` Shape 的 `text_frame` 內（不是疊加獨立文字框），避免點擊選取衝突。
  - 料件名稱：獨立 `TextBox`。
  - 扭力方框：獨立 `RoundedRectangle`（線寬 `Pt(0.75)`，比早期版本細很多）。
  - 箭頭：`add_connector`，紅色。
  - 全部文字統一設定字型為 `Microsoft JhengHei`。
  - `marker_only=True` 的標記只輸出圓圈，不輸出名稱/方框/箭頭。
- **複製為 PowerPoint 物件（可編輯）**：透過 `pywin32` 呼叫本機安裝的 PowerPoint COM，背景開啟剛產生的暫存 PPTX，選取所有 Shape 執行 `Shape.Copy()`，放進 Windows 剪貼簿，使用者可在自己的簡報按 `Ctrl+V` 貼上可編輯物件。失敗會跳出錯誤訊息並保留「另存 PPTX」、「複製合成圖片」作為備援，不會讓程式當掉。**這個功能目前有做出來，但還沒有機會實際請你完整測試過貼上後的效果**（v0.6 首次加入後，後續迭代重點轉去修操作模式，尚待回頭驗證）。
- **複製合成圖片（僅供備援）**：透過 `win32clipboard` 把 PNG 合成圖放進剪貼簿，貼上後是死圖。
- **另存專案 JSON**：儲存 `source_image` 路徑、`annotations` 清單、`components` 清單，方便之後重新開啟（但**目前還沒有做「開啟專案 JSON」還原畫面的功能**，只能存、不能讀回來）。

## 2. 已知限制 / 尚未完成（誠實列出，避免下個 session 誤以為做完了）

1. **PowerPoint 群組化未完成**：說好的「同一元件的圓圈、箭頭、名稱、扭力框群組成一個 PowerPoint Group（不含主圖片）」還沒實作，目前每個元素在 PPTX 裡都是各自獨立物件，沒有自動 `Group()`。
2. **分層標記清單未完成**：右側清單目前是平面清單，還沒有你設計的「群組/動作」分層結構、`Tab` 建群組、`Ctrl/Shift` 多選、清單拖曳排序。
3. **共用說明文字＋多箭頭未完成**：目前每個標記各自獨立顯示名稱與扭力，還沒做「同群組多個標記共用一個說明文字框、多條箭頭從同一文字框延伸」的邏輯，也還沒做「群組內第一個顯示、其餘預設僅標記，可手動覆蓋」的規則。
4. **標記本身還不能拖曳移動**：目前建立後位置就固定，只能刪除「最後一個」重建，無法拖曳調整既有標記位置、也不能雙擊既有標記重新編輯內容（目前雙擊行為是綁在料件清單上的「快速新增」，不是編輯既有標記）。
5. **參考圖片（`reference_image` 欄位）尚未實際使用**：Excel/YAML 已經有這個欄位，但 PNG/PPTX 輸出都還沒把參考圖片實際貼進版面。
6. **開啟既有專案 JSON 還原畫面**尚未實作，只能存檔不能讀回。
7. **PowerPoint 複製功能尚未經過你完整驗證**：包含「貼上後圓圈能否單獨選取」、「文字能否雙擊修改」、「中文字型在 PowerPoint 內是否正確」等，需要回頭專門測試一次。
8. **尚未打包成 EXE**（PyInstaller），目前都是用 `python xxx.py` 直接執行，還沒有給非工程背景同事使用的單檔可執行版本。
9. **尚未做正式的單元測試/自動化測試**，目前都是手動人工測試。
10. **O-ring／塗矽油資訊目前只在「設定標記」對話框的規格提示區顯示**，還沒有輸出到 PNG/PPTX 的版面上（目前輸出只有料件名稱＋扭力，沒有額外顯示 O-ring 規格或塗矽油說明文字）。

## 3. 下一步開發順序（按優先度排列，一次只做一小版）

### 步驟 A：驗證 PowerPoint 複製功能（優先，因為做了但沒驗證過）

- 目標：確認「複製為 PowerPoint 物件」按鈕產生的物件貼到真實簡報後，圓圈、文字、方框、箭頭都能個別選取、移動、修改文字。
- 測試方式：v0.9.1 建立至少 2 個標記（一個有扭力、一個無需扭力），按「複製為 PowerPoint 物件」，到 PowerPoint 按 `Ctrl+V`，逐一點擊確認可編輯性。
- 若失敗，需回報完整錯誤訊息文字，依實際錯誤調整 COM 呼叫方式。

### 步驟 B：標記可拖曳與重新編輯（小版本，範圍明確）

- 允許點擊選取既有標記後，拖曳圓圈改變位置（更新 `x`/`y`）。
- 允許雙擊既有標記，重新開啟 `AnnotationDialog` 修改扭力/單位/順序/僅標記。
- 加入「刪除選取的標記」（不只能刪最後一個）。

### 步驟 C：分層群組清單（範圍較大，資料模型要擴充）

- 新增 `group_id` 欄位到 `Annotation`。
- 右側清單改為可勾選、可拖曳排序、支援 `Ctrl/Shift` 多選。
- 多選後按 `Tab` 建立群組（只支援單層，群組內不能再有子群組）。
- 建立群組時，系統自動把第一個項目設為顯示（`marker_only=False`），其餘自動設為 `marker_only=True`，之後使用者可個別手動覆蓋。

### 步驟 D：共用說明文字＋多箭頭延伸（依賴步驟 C 完成）

- 邏輯：每個群組找「第一個 `marker_only=False` 的項目」作為 `label_owner`，提供共用文字框。
- 群組內 `marker_only=True` 的項目，箭頭從 `label_owner` 的文字框延伸到自己的圓圈。
- 若群組內**全部**項目都是 `marker_only=True`（沒有 `label_owner`），則不畫任何箭頭，只顯示圓圈（已確認的規則：選項 A）。
- 說明文字框在畫布上要可拖曳，拖曳時所有連到它的箭頭終點需要重新計算。
- PNG 與 PPTX 輸出都要同步支援「一個文字框、多條箭頭」的畫法。

### 步驟 E：PowerPoint 元件群組化

- 依賴步驟 C／D 的資料結構，在 `export_pptx()` 或 `copy_pptx_shapes()` 中，透過 PowerPoint COM 的 `Group()` 方法，把同一群組（或同一標記＋其說明文字/方框/箭頭）合併成一個 PowerPoint Group，主圖片維持獨立不群組。

### 步驟 F：參考圖片輸出

- 從 Excel/YAML 的 `reference_image` 欄位讀取檔案路徑（相對於規格檔案所在資料夾）。
- 在 PNG 合成圖與 PPTX 中，把參考圖片貼到標記旁邊（獨立 Picture，不強制群組）。
- 需要決定參考圖片的預設大小與位置規則（例如固定寬度、貼在說明文字框右側）。

### 步驟 G：開啟既有專案 JSON

- 新增「開啟專案」按鈕，讀取 JSON，還原：主圖片路徑、料件清單、所有標記（含群組、僅標記狀態）、選取狀態。
- 需要處理「圖片路徑已經失效／被移動」的錯誤情況，跳出提示讓使用者重新選擇圖片。

### 步驟 H：測試與 EXE 打包（最後階段）

- 補齊 P0/P1/P2 測試項目（詳見計畫書 `SOP_Helper_計畫書與規格_v1.md` 第 11～12 節，那份文件的測試框架仍然有效，可以直接拿來對照目前版本）。
- 用 `PyInstaller` 打包成單一 `SOP_Helper.exe`。
- 在沒有安裝 Python 的乾淨 Windows 環境測試 EXE 是否能獨立執行。
- 找一位不熟悉程式的同事做使用者驗收測試（無口頭協助，10 分鐘內完成基本流程）。

## 4. 給下一個 session 的操作提示

如果你是接手這個專案的新對話 session，請注意：

1. 使用者已有 Windows 本機開發環境（`.venv` 已建立、套件已安裝），**不需要重新引導安裝 Python 或建立虛擬環境**，除非使用者明確說環境壞了。
2. 使用者偏好**一步一步小範圍修改**，每次改完都要先讓他測試、明確說「ok」或指出問題後才進行下一步，不要一次塞多個功能。
3. 使用者是製程工程師，重視技術細節與可操作步驟，說明時可以直接給程式碼、指令、清單，不需要過度簡化。
4. 目前最新可用版本是 **v0.9.1**（檔名 `SOP_Helper_MVP_v0_9_1.py`），這是接下來開發的起點，不要從更早版本繼續改。
5. 每次生成新版本，請用 `create_file` 工具產生完整可執行的單一 `.py` 檔案（不要用 diff 或片段），檔名遞增版本號（例如 `v1_0`），方便使用者對照與回溯。
6. 修改時盡量保持既有的資料結構命名（`Component`、`Annotation`、`export_pptx`、`render_composite` 等），除非該步驟本身就是要擴充資料結構（如步驟 C 的 `group_id`）。
7. 這份文件本身也應該隨版本更新；當完成步驟 A、B、C...時，應更新「已完成」與「已知限制」章節，並重新輸出一份新版進度文件。
